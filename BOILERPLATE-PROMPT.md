# Prompt — Recreate the API boilerplate (NestJS + CQRS + Prisma + GraphQL + REST)

> Copy everything after the `---` line into an AI agent (Claude Code, etc.) at the root of an
> empty folder. Replace `<app-name>` with the project name.

---

## Role and goal

You are a senior backend developer. Create **from scratch** a **NestJS 12 / TypeScript** API
boilerplate named `<app-name>`, production-ready, with a strict **CQRS** core, **Prisma**
persistence (PostgreSQL) and **two thin transports** that drive exactly the same
commands/queries:

- **GraphQL** (code-first, Mercurius);
- **REST** (Nest controllers, **Zod** DTOs, **OpenAPI/Swagger** documentation generated from Zod).

The boilerplate contains **no business logic** specific to any domain, except two demonstration
features that serve as models to copy, exposed on both transports:

1. **`user`**: local sign-up / sign-in, refresh token with rotation, logout, `me`.
2. **`project`**: full CRUD of a resource owned by a user (serves as the reference for any new
   feature).

The code must compile (`pnpm build`), pass lint (`biome ci .`) and the tests (`pnpm test`) at the
end. Leave no TODO and no dead code. Before writing the Prisma layer, check the documentation of
the installed Prisma version (generator, `prisma.config.ts`, driver adapter) and follow it if it
differs from a detail of this prompt.

## Guiding principle (non-negotiable)

> Transport adapters **never** contain business logic. They translate a request into a
> Command/Query, dispatch it on the bus, then translate the result into a response type.
> Everything that decides *what happens* lives in the domain layer.

Dependency direction, one way only: `api` → `domain` → `infrastructure`. `shared` depends on no
one and can be imported anywhere. **Only `infrastructure/database/` knows Prisma**: no type
generated by Prisma (`@/infrastructure/database/generated/...`) is imported in `domain/`, `api/`
or `shared/`. `api/` **never** imports `infrastructure/database` (single exception: the
`JwtStrategy`, which reads the `UserRepository`).

## Validation rule: who uses what

| Zone | Tool | Forbidden |
|---|---|---|
| Configuration (`shared/config/*`, `database.config.ts`, `prisma.config.ts`) | **Zod only** | Joi, class-validator, reading `process.env` directly outside these files |
| REST layer (`api/rest/**`): request DTOs, params, query string, responses, errors | **Zod only** via `nestjs-zod` (`createZodDto`); Swagger docs come from the Zod schemas (`.describe()`, `.meta()`) | class-validator, hand-written `@ApiProperty` on a Zod DTO |
| Domain (Commands / Queries) | class-validator (a safety net independent of the transport) | Zod |
| GraphQL (`@InputType`) | class-validator (required by code-first `@nestjs/graphql`) | Zod |

**Joi is not installed.** Zod is the only schema library for configuration and REST.

## 1. Bootstrap and modules

### `main.ts`
- `NestFactory.create<NestFastifyApplication>(AppModule, new FastifyAdapter({ trustProxy: true }), { bufferLogs: true, logger: new ConsoleLogger({ json: true, colors: false }) })`.
- `app.useLogger(app.get(PinoNestLogger))`.
- `useContainer(app.select(AppModule), { fallbackOnErrors: true })` (to inject services into
  custom class-validator constraints).
- `app.enableVersioning({ type: VersioningType.URI })` (REST routes under `/v1/...`).
- `enableCors()`, `enableShutdownHooks()` (triggers Prisma's `$disconnect`).
- If `appConfig.nodeEnv !== 'production'`: `setupSwagger(app)` (UI on `/docs`, JSON on
  `/docs-json`), same policy as GraphiQL/introspection.
- `listen(appConfig.port, '0.0.0.0')`.
- **The application applies neither migrations nor seeds at startup**: that is the role of
  `prisma migrate deploy` / `prisma db seed`, run before deployment (see §10).
- `bootstrap().catch(err => { bootstrapLogger.fatal(err, 'Bootstrap'); process.exit(1) })`.

### `AppModule`
`imports: [InfrastructureModule, DomainModule, ApiCommonModule, GraphqlApiModule, RestApiModule]`,
and nothing else.

### `InfrastructureModule` (`@Global()`)
- `imports`:
  - `ConfigModule.forRoot({ isGlobal: true, load: [APP_CONFIG] })`, `CqrsModule.forRoot()`;
  - `DatabaseModule`;
  - `ClsModule.forRoot({ global: true, middleware: { mount: true, setup: (cls, req) => cls.set(CORRELATION_ID_KEY, resolveCorrelationId(req)) }, plugins: [new ClsPluginTransactional({ imports: [DatabaseModule], adapter: new TransactionalAdapterPrisma({ prismaInjectionToken: PrismaService }) })] })`
    — a single `ClsModule`, shared by the logger (correlation id) and the transactions;
  - `AppLoggerModule`, `AppI18nModule`, `AdaptersModule`.
- `providers`: `...Object.values(repositories)`.
- `exports`: the same providers + `DatabaseModule` + `AdaptersModule` + `AppLoggerModule`.

### `DomainModule`
- `imports`: `CqrsModule` (without `forRoot`), `InfrastructureModule`,
  `ConfigModule.forFeature(JWT_CONFIG)`, `JwtModule.registerAsync(...)` fed by the JWT config.
- `providers`: `...Object.values(<feature>Handlers)` for each feature + the domain services.
  **Adding a handler = exporting it from its feature's barrel**, no other list to maintain.

### `ApiCommonModule`: shared base for both transports
Cross-cutting behaviors exist **only once** and can serve both contexts
(`context.getType<GqlContextType>()` is either `'graphql'` or `'http'`):
- `imports`: `PassportModule`, `ThrottlerModule.forRoot([{ ttl: 60000, limit: 60 }])`,
  `ConfigModule.forFeature(JWT_CONFIG)`.
- `providers`: `JwtStrategy`, and globally: `APP_GUARD` → `JwtAuthGuard`, `APP_GUARD` →
  `AppThrottlerGuard`, `APP_FILTER` → `AppExceptionFilter`, `APP_INTERCEPTOR` →
  `ErrorCodeOnFailureInterceptor`.

### `GraphqlApiModule`
- `imports`: `CqrsModule`, `GraphQLModule.forRootAsync<MercuriusDriverConfig>` with
  `MercuriusDriver` and a factory that injects `ConfigService`, `LoggerService`, `I18nService`:
  - `autoSchemaFile`: path `src/schema.gql` in production, `true` otherwise; `sortSchema: true`;
  - `graphiql` and `introspection` disabled in production;
  - `context: (req, reply) => { logger.assign({ graphql: describeGraphqlRequest(req.body) }); return { req, reply } }`;
  - `errorFormatter`: logs the errors that did not reach the filter, then
    `createGraphqlErrorResponse(i18n)`.
- `providers`: `JSONScalar`, `...Object.values(resolvers)`, `...Object.values(dataloaders)`,
  `APP_PIPE` → `ClassValidatorPipe`.
- `ClassValidatorPipe extends ValidationPipe` (`forbidUnknownValues: true`,
  `exceptionFactory: errors => new BadRequestException(errors)`), overriding
  `toValidate(metadata)` to return `false` when `isZodDto(metadata.metatype)` (from
  `nestjs-zod`): `APP_PIPE` pipes are global, so each pipe must ignore the DTOs of the other
  transport.

### `RestApiModule`
- `imports`: `CqrsModule`.
- `controllers`: `...Object.values(controllers)`.
- `providers`: `APP_PIPE` → `AppZodValidationPipe` (natively ignores anything that is not a Zod
  DTO), `APP_INTERCEPTOR` → `ZodSerializerInterceptor` (validates/filters the responses decorated
  with `@ZodSerializerDto`).
- Neither transport module imports `DomainModule`: the bus is available thanks to the global
  module.

## 2. Configuration: Zod only

### `shared/config/parse-env.ts`
```ts
import { z } from 'zod'

/**
 * Validates process.env with a Zod schema. z.object() ignores unknown
 * variables; all errors are reported at once.
 */
export function parseEnv<TSchema extends z.ZodType>(
  schema: TSchema,
  name: string,
  env: NodeJS.ProcessEnv = process.env,
): z.output<TSchema> {
  const result = schema.safeParse(env)
  if (!result.success) {
    throw new Error(
      `❌ ${name} environment validation error:\n${z.prettifyError(result.error)}`,
    )
  }
  return result.data
}
```

### One file per config domain
Each `<name>.config.ts` exports a key, a Zod schema of the environment variables, the config type
(derived from the schema or mapped explicitly) and a `registerAs`:

```ts
export const JWT_CONFIG_KEY = 'jwt'

const JwtEnvSchema = z.object({
  JWT_SECRET: z.string().min(1),
  JWT_EXPIRES_IN: z.coerce.number().int().positive(),
  REFRESH_TOKEN_EXPIRES_IN: z.coerce.number().int().positive(),
  REFRESH_TOKEN_GRACE_PERIOD: z.coerce.number().int().min(0).default(20),
})

export type JwtConfig = {
  secret: string
  expiresIn: number
  refreshTokenExpiresIn: number
  refreshTokenGracePeriod: number
}

export const JWT_CONFIG = registerAs(JWT_CONFIG_KEY, (): JwtConfig => {
  const env = parseEnv(JwtEnvSchema, 'JWT')
  return {
    secret: env.JWT_SECRET,
    expiresIn: env.JWT_EXPIRES_IN,
    refreshTokenExpiresIn: env.REFRESH_TOKEN_EXPIRES_IN,
    refreshTokenGracePeriod: env.REFRESH_TOKEN_GRACE_PERIOD,
  }
})
```

Consumed via `configService.getOrThrow<JwtConfig>(JWT_CONFIG_KEY)` or
`@Inject(JWT_CONFIG.KEY) config: ConfigType<typeof JWT_CONFIG>`. Zod conventions for the env:
numbers `z.coerce.number()`, booleans `z.stringbool()` (never `z.coerce.boolean()`, which makes
`"false"` true), enumerations `z.enum([...])`, CSV lists
`z.string().default('').transform(csv).pipe(z.array(z.enum(LEVELS)))`.

Configs to create:
- `app`: `NODE_ENV` (`z.enum(['development', 'test', 'production']).default('development')`),
  `PORT` (default 3000);
- `database` (in `infrastructure/database/database.config.ts`): `DATABASE_URL`
  (`z.url()` whose protocol is `postgres:`/`postgresql:`), `DB_POOL_MAX`
  (`z.coerce.number().int().positive().default(10)`). Also exports a function
  `loadDatabaseEnv()` reused as-is by `prisma.config.ts` (which therefore does not read
  `process.env` itself);
- `jwt`: see the example above;
- `logger`: `LOG_LEVELS`, a CSV list of `trace|debug|info|warn|error|fatal`, without duplicates,
  default `warn,error`.

`.env.example`:


## 3. Domain layer: CQRS

### Commands
- Extend `Command<TResult>`; `readonly` fields decorated with `class-validator` (`@IsUUID()`,
  `@IsString()`, `@IsOptional()`, custom decorators from `shared/decorators`).
- Constructor taking a **parameter object** typed `XxxParams` (derived with `Pick<>` from the
  command's fields) and applied with `Object.assign`.

```ts
export class CreateProjectCommand extends Command<Project> {
  @IsOptional()
  @IsUUID('4')
  readonly id?: string

  @IsString()
  @IsNotEmpty()
  readonly name: string

  @IsUUID()
  readonly userId: string

  constructor({ ownerId, ...params }: CreateProjectParams) {
    super()
    Object.assign(this, { ...params, userId: ownerId })
  }
}

export type CreateProjectParams = Pick<CreateProjectCommand, 'id' | 'name'> & {
  ownerId: string
}
```

### Queries
Same shape, extending `Query<TResult>`. Positional arguments are allowed when there are only one
or two fields (`new GetProjectQuery(id, userId)`).

### Base handler classes: `src/utils/cqrs.utils.ts`
Write `AppCommandHandler<TCommand extends Command<TResult>, TResult>` and
`AppQueryHandler<TQuery extends Query<TResult>, TResult>`:
- constructor `(protected readonly logger: LoggerService, private readonly originType: 'user' | 'system', private readonly operationName: string)`;
- `async execute(payload)`: calls `validatePayload()` then `this.handle(payload)`;
- `abstract handle(payload): Promise<TResult>`;
- `validatePayload` runs `validate(data, { forbidUnknownValues: false })`; on error, retrieves
  the messages via `new ValidationPipe().createExceptionFactory()` and throws
  `CQRSValidationException({ data: structuredClone(data), operationName, originType, validationErrors, fields: toErrorFields(errors) })`.

### Concrete handlers
```ts
@CommandHandler(CreateProjectCommand)
export class CreateProjectHandler extends AppCommandHandler<CreateProjectCommand, Project> {
  constructor(
    private readonly projectRepository: ProjectRepository,
    logger: LoggerService,
  ) {
    super(logger, 'user', CreateProjectCommand.name)
    this.logger.setContext(CreateProjectHandler.name)
  }

  handle(command: CreateProjectCommand): Promise<Project> {
    return this.projectRepository.create(
      { id: command.id ?? randomUUID(), name: command.name },
      command.userId,
    )
  }
}
```

Rules:
- 1 handler = 1 command/query; no switch on a "type" field.
- A handler returns a **domain model** (`shared/types`), never a Prisma record, a GraphQL type or
  a REST DTO.
- Multi-entity orchestration happens in the handler (inside a transaction if needed) or in the
  repository, never in the resolver/controller.
- `originType: 'system'` for operations triggered by the server (cron, sync): a validation error
  becomes a 500 there, not a 400.

### Domain models: `shared/types/`
Pure classes, with no dependency on Prisma, constructor with `readonly` parameters. Business enums
(`AuthProvider`…) are declared here with the same values as the Prisma enums; the mapping is done
by the mappers (§4), never by importing the generated enum.

### Transactions
The domain never sees a Prisma client. A handler that must group several writes puts
`@Transactional()` (from `@nestjs-cls/transactional`) on its `handle` method: the Prisma
transaction is opened and propagated by CLS, and all repositories called within it use it
automatically. No `tx`/`manager` parameter travels through the signatures.

```ts
@Transactional()
async handle(command: DeleteProjectCommand): Promise<void> {
  await this.taskRepository.detachFromProject(command.id, command.userId)
  await this.projectRepository.softDelete(command.id, command.userId)
}
```

Outside an HTTP request (script, cron), open a context with `cls.run(() => ...)` before calling a
transactional handler.

## 4. Infrastructure layer: Prisma persistence

### `prisma/schema.prisma`
```prisma
generator client {
  provider     = "prisma-client"
  output       = "../src/infrastructure/database/generated/prisma"
  moduleFormat = "cjs"
}

datasource db {
  provider = "postgresql"
}
```
(the URL comes from `prisma.config.ts`, see below).

Modeling conventions:
- Models in singular `PascalCase`, tables in plural `snake_case` via `@@map("projects")`;
  fields in `camelCase`, columns in `snake_case` via `@map("owner_id")`.
- Ids `String @id @db.Uuid`: `@default(uuid())` unless the id can come from the client
  (offline-first), in which case there is no `@default` and the handler provides `randomUUID()`.
- Dates `DateTime @db.Timestamptz(6)`: `createdAt @default(now())`, `updatedAt @updatedAt`,
  `deletedAt DateTime?` for soft delete.
- Explicit foreign key (`ownerId String @map("owner_id") @db.Uuid`) + relation
  (`owner User @relation(fields: [ownerId], references: [id])`), `@@index([ownerId])`.

Models to create: `User` (id, email `@unique`, createdAt, updatedAt, relations `authMethods`,
`sessions`, `projects`), `AuthMethod` (enum `AuthProvider { LOCAL }`, `providerId` = argon2 hash
for LOCAL, `userId`, `@@unique([provider, userId])`), `UserSession` (refreshTokenHash,
previousRefreshTokenHash?, rotatedAt?, expiresAt, ipAddress?, userAgent?, userId,
`onDelete: Cascade`), `Project` (id, name, isActive `@default(true)`, ownerId/owner, createdAt,
updatedAt, deletedAt?).

### `prisma.config.ts`
`defineConfig` (from `prisma/config`) with `schema: 'prisma/schema.prisma'`,
`migrations: { path: 'prisma/migrations', seed: 'ts-node -r tsconfig-paths/register prisma/seed.ts' }`
and `datasource: { url: loadDatabaseEnv().DATABASE_URL }` (Zod validation shared with the app).

### `PrismaService` (`database/prisma.service.ts`)
```ts
@Injectable()
export class PrismaService
  extends PrismaClient
  implements OnModuleInit, OnModuleDestroy
{
  constructor(@Inject(DATABASE_CONFIG.KEY) config: ConfigType<typeof DATABASE_CONFIG>) {
    super({
      adapter: new PrismaPg({ connectionString: config.url, max: config.poolMax }),
    })
  }

  async onModuleInit(): Promise<void> {
    await this.$connect()
  }

  async onModuleDestroy(): Promise<void> {
    await this.$disconnect()
  }
}
```
`DatabaseModule`: `imports: [ConfigModule.forFeature(DATABASE_CONFIG)]`,
`providers/exports: [PrismaService]`. The client is imported from the `generated/` folder, not
from `@prisma/client`.

### Mappers (`database/mappers/`)
The **only** place that converts a Prisma record into a domain model:

```ts
import type { Project as ProjectRecord } from '../generated/prisma/client'

export function toProject(record: ProjectRecord): Project {
  return new Project(
    record.id,
    record.name,
    record.isActive,
    record.createdAt,
    record.updatedAt,
    record.deletedAt,
  )
}
```
Generated types are always aliased as `XxxRecord` so they are never confused with the domain
model of the same name. This is what makes persistence replaceable: changing ORM only touches
`infrastructure/database/`.

### Repositories (`database/repositories/`)
- One per aggregate, `@Injectable()`, inject
  `TransactionHost<TransactionalAdapterPrisma<PrismaService>>` and `LoggerService` (+ `setContext`).
  They **always** go through `this.txHost.tx.<model>`: outside a transaction it is the regular
  client, inside a `@Transactional()` handler it is the transaction's client.
- Methods with explicit names and narrow signatures: `findByIdAndUserId`, `existsByIdAndUserId`,
  `findByIds`, `findAllByOwner`, `create`, `update`, `softDelete`. **No** generic method that
  accepts a `where`/`Prisma.XxxWhereInput` supplied by the caller.
- Explicit `select`/`include` when not all columns are needed or when a relation is loaded.
- Soft delete is filtered explicitly: every read adds `deletedAt: null` (the `NOT_DELETED`
  constant shared by the repositories).
- Return **domain models** through the mappers, never a record.
- A lookup that is expected to find something and fails throws
  `new NotFoundError('Project not found', { code: ErrorCode.PROJECT_NOT_FOUND })`; a batch lookup
  (`findByIds`) returns `[]`.
- Any write that may fail on a constraint is wrapped by `rethrowPrismaError` (see below).

```ts
@Injectable()
export class ProjectRepository {
  constructor(
    private readonly txHost: TransactionHost<TransactionalAdapterPrisma<PrismaService>>,
    private readonly logger: LoggerService,
  ) {
    this.logger.setContext(ProjectRepository.name)
  }

  async create(data: { id: string; name: string }, ownerId: string): Promise<Project> {
    const record = await this.txHost.tx.project.create({
      data: { ...data, ownerId },
    })
    return toProject(record)
  }

  async findByIdAndUserId(id: string, userId: string): Promise<Project> {
    const record = await this.txHost.tx.project.findFirst({
      where: { id, ownerId: userId, ...NOT_DELETED },
    })
    if (!record) {
      throw new NotFoundError('Project not found', { code: ErrorCode.PROJECT_NOT_FOUND })
    }
    return toProject(record)
  }

  async findByIds(ids: string[]): Promise<Project[]> {
    if (ids.length === 0) return []
    const records = await this.txHost.tx.project.findMany({
      where: { id: { in: ids }, ...NOT_DELETED },
    })
    return records.map(toProject)
  }
}
```

### Prisma errors (`database/prisma-errors.ts`)
`rethrowPrismaError(error, codes: { notFound?: ErrorCode; conflict?: ErrorCode }): never`:
`PrismaClientKnownRequestError` `P2002` (unique constraint) → `ConflictError` with `codes.conflict`
(`details.target` = conflicting fields), `P2025` (record not found) → `NotFoundError` with
`codes.notFound`, `P2003` (foreign key) → `BadRequestError`; everything else is rethrown as-is
(and becomes an `InternalError` in the filter). Example: sign-up maps `P2002` to `USER_EXISTS`.
The `api/` layer therefore never knows about Prisma codes.

### Migrations and seed
- Development: `pnpm db:migrate --name <change>` (`prisma migrate dev`) generates the SQL in
  `prisma/migrations/<timestamp>_<change>/migration.sql`; the SQL is **reviewed and versioned**.
- Production: `pnpm db:deploy` (`prisma migrate deploy`) in the `migrate` step of the image
  (§10), before the new version starts. Never `migrate dev` or `db push` in production.
- Generates an initial `init` migration matching the models.
- `prisma/seed.ts`: only `upsert` calls (replayable at will), run by `pnpm db:seed` and after
  `migrate deploy` in the `migrate` step.

### Adapters (`infrastructure/adapters/`)
Folder reserved for external integrations **outside the DB** (third-party APIs, AI SDKs…). Each
integration has its own subfolder, its request/response schemas (Zod), and its Zod config via
`ConfigModule.forFeature(...)` in `adapters.module.ts`. An adapter knows nothing about the DB; a
repository knows nothing about adapters. Handlers inject them like repositories.
In the boilerplate, create an empty `adapters.module.ts` (providers/exports `[]`), ready to use.

### Logger (`infrastructure/logger/`)
- `AppLoggerModule`: `PinoLoggerModule.forRootAsync` with: filtering by the exact set of
  `LOG_LEVELS` (`logMethod` hook), `autoLogging: false`, `messageKey: 'message'`, levels mapped to
  Cloud Logging `severity` (`DEBUG/INFO/WARNING/ERROR/CRITICAL`), `genReqId: resolveCorrelationId`,
  `customAttributeKeys: { reqId: 'correlationId' }`, redaction of `req.headers.authorization` and
  `req.headers.cookie`, `stdSerializers.errWithCause` serializers, a single-line `pino-pretty`
  transport outside production. The `ClsModule` is the one from `InfrastructureModule`.
- `resolveCorrelationId(req)`: reuses `x-correlation-id` / `x-request-id`, otherwise
  `crypto.randomUUID()`, memoized on the request via a `Symbol`.
- `LoggerService` (`Scope.TRANSIENT`): wraps `PinoLogger` + `ClsService`, methods
  `trace/debug/info/warn/error/fatal`, `setContext(name)`, `assign(fields)` (bound to all the
  following logs of the request). It merges `correlationId` + assigned fields into every log,
  turns an `Error` passed as first argument into `{ err }`, and logs without bindings outside a
  request.
- `redactSecrets(obj)`: recursively masks sensitive keys (`password`, `token`,
  `refreshToken`, `secret`, `authorization`…) before logging `details`.
- In development, logs slow Prisma queries at `debug` level via `$on('query')` (duration above a
  threshold), never their parameters.

### i18n (`infrastructure/i18n/`)
- `AppI18nModule`: `I18nModule.forRoot({ fallbackLanguage: DEFAULT_LOCALE, loaderOptions: { path: path.join(__dirname, '../../i18n'), watch: NODE_ENV === 'development' }, resolvers: [AcceptLanguageResolver] })`.
- `src/i18n/<lang>/errors.json` (key = error code) and `validation.json`, which contains:
  the class-validator constraints at the root (`isEmail`, `isNotEmpty`…, + `default`) and a `zod`
  object indexed by Zod 4 issue code (`invalid_type`, `too_small`, `too_big`,
  `invalid_format`, `invalid_value`, `not_multiple_of`, `unrecognized_keys`, `invalid_union`,
  `invalid_key`, `invalid_element`, `custom`). `nest-cli.json` copies `i18n/**/*.json` into `dist`.
- `shared/i18n/locale.ts`: `SUPPORTED_LOCALES = ['fr', 'en'] as const`, `DEFAULT_LOCALE = 'fr'`,
  `resolveLocale(acceptLanguage)` which parses the q-values, ignores regions, and falls back to
  the default.
- `translations.spec.ts`: fails if a key of `ERROR_CODES` is missing in a language, if a file
  contains an unknown key, if a Zod issue code is not translated, or if the languages do not have
  the same validation keys.

## 5. Error handling (shared by both transports)

### `shared/errors/app-error.ts`
`abstract class AppError extends Error` with `abstract statusCode`, `code`, `details?` (logged
only), `params?` (i18n interpolation), `fields?: { field, constraint }[]`, public extensions, an
`extensions` getter (`{ ...public, code }`) and an `expected` getter (`statusCode < 500`).
Subclasses: `BadRequestError` (400, `BAD_REQUEST`), `UnauthenticatedError` (401),
`ForbiddenError` (403), `NotFoundError` (404), `ConflictError` (409),
`BusinessRuleError(code, message)` (422), `TooManyRequestsError` (429), `InternalError` (500,
neutral message by default). The first argument (message) is **only** logged.

### `shared/errors/error-codes.ts`
`enum ErrorCode` + `ERROR_CODES: Record<ErrorCode, { expected: boolean; description: string }>`
+ `isErrorCode(code)`. This is the contractual inventory: codes are added, and never renamed or
removed. Boilerplate codes: `BAD_REQUEST, UNAUTHENTICATED, FORBIDDEN, NOT_FOUND,
CONFLICT, TOO_MANY_REQUESTS, VALIDATION_FAILED, INTERNAL_SERVER_ERROR, GRAPHQL_INVALID_QUERY,
INVALID_CREDENTIALS, USER_EXISTS, USER_NOT_FOUND, PROJECT_NOT_FOUND`.

### `CQRSValidationException extends AppError`
Origin `user` → 400 `VALIDATION_FAILED` with `extensions.validationErrors` and `fields`;
origin `system` → 500 `INTERNAL_SERVER_ERROR` without exposing the details. `details` contains
`operationName`, `originType`, `data`.

### Invalid fields
- `toErrorFields(errors, parentPath?)` (`shared/errors/validation-fields.ts`): flattens the
  class-validator `ValidationError`s into `{ field: 'a.0.b', constraint: 'isEmail' }[]`.
- `toZodErrorFields(error: ZodError)` (`api/rest/validation/zod-error-fields.ts`):
  `error.issues.map(issue => ({ field: issue.path.join('.'), constraint: \`zod.${issue.code}\` }))`.
Both produce the same `ErrorField`, so translation and the client format are identical whichever
library performed the validation.

### Shared base (`api/common/`)
1. **`toAppError(exception)`**: an `AppError` as-is; an `HttpException` mapped by status (a
   `BadRequestException` containing class-validator `ValidationError`s becomes
   `VALIDATION_FAILED` with `fields`); everything else (including a Prisma error not translated
   by a repository) → `InternalError` with `cause`.
2. **`errorTranslator(i18n, lang)`**: `{ error(code, params), constraint(name) }` falling back to
   `validation.default`; an uncatalogued code → the generic code for the status
   (400/401/403/404/409/422/429), so a client never receives an untranslated message.
3. **`AppExceptionFilter`** (`@Catch()`, global): the only place that **logs** an error thrown
   during a request. Expected error → a single `warn` line without stack; otherwise `error` with
   stack and causes, `details` passed through `redactSecrets`, and the message masked
   (`InternalError`) in production. Then it routes based on `host.getType<GqlContextType>()`:
   - `'graphql'`: logs `operation: Parent.field` + `path` and **returns** the `AppError`
     (graphql-js locates it, the `errorFormatter` translates it);
   - `'http'`: builds the body with `formatRestError(error, translator)` (language from
     `resolveLocale(request.headers['accept-language'])`) and replies
     `reply.status(error.statusCode).send(body)` on the `FastifyReply`.
4. **`@ErrorCodeOnFailure(code)`** + **`ErrorCodeOnFailureInterceptor`**: replaces the generic
   `INTERNAL_SERVER_ERROR` with the action's code; leaves specific codes and client errors
   untouched. Works for a resolver as well as for a route.

### GraphQL specifics
- **`createGraphqlErrorResponse(i18n)`** (mercurius errorFormatter): HTTP is **always 200**; for
  each error, a translated `message`, `extensions.code`, `extensions.fields: { field, message }[]`.
  An error without `path` (invalid document) → `GRAPHQL_INVALID_QUERY`. Flattens the nested
  validation errors of mercurius (`MER_ERR_GQL_VALIDATION`).
- **`ErrorResolver`**: public query `errorCodes: [ErrorCode!]!`
  (`registerEnumType(ErrorCode, { name: 'ErrorCode' })`).

### REST specifics
- The **real HTTP status** = `error.statusCode` (400, 401, 404, 409, 422, 429, 500).
- Body (`formatRestError`) conforming to `ErrorResponseSchema`:

```ts
export const ErrorResponseSchema = z
  .object({
    code: z.enum(ErrorCode).describe('Stable code the client branches its logic on'),
    message: z.string().describe("Message translated according to Accept-Language, displayable as-is"),
    fields: z
      .array(z.object({ field: z.string(), message: z.string() }))
      .optional()
      .describe('Invalid fields (VALIDATION_FAILED only)'),
    correlationId: z.string().describe('To be provided to support'),
  })
  .meta({ id: 'ErrorResponse' })

export class ErrorResponseDto extends createZodDto(ErrorResponseSchema) {}
```

- `@ApiErrorResponses(...statuses)` (`api/rest/errors/api-error-responses.decorator.ts`):
  `applyDecorators` of `@ApiResponse({ status, type: ErrorResponseDto })` for each status, so
  that each route documents its errors in Swagger. The `ErrorCode` enumeration thus appears typed
  in the OpenAPI document (the REST equivalent of the `errorCodes` query).

Recipe to add an error: code in `ERROR_CODES` → message in `fr/errors.json` and
`en/errors.json` → `throw new NotFoundError('…', { code: ErrorCode.X })`. Nothing to change on the
transport side.

## 6. Auth (shared by both transports)

- `JwtStrategy` (`passport-jwt`, Bearer, `ignoreExpiration: false`): payload
  `{ sub, email, sid }`, checks that the user exists, returns
  `AuthenticatedUser = { id, email, sessionId }`.
- `JwtAuthGuard extends AuthGuard('jwt')` (global): `getRequest(context)` returns
  `GqlExecutionContext.create(context).getContext().req` under GraphQL, otherwise
  `context.switchToHttp().getRequest()`; lets the request through if the `isPublic` metadata is set.
- `AppThrottlerGuard extends ThrottlerGuard`: `getRequestResponse` returns `{ req, res: reply }`
  from the GraphQL context, otherwise from `switchToHttp()`.
- `@Public()` = `SetMetadata('isPublic', true)`.
- `@CurrentUser()`, `@CurrentSessionId()`, `@ClientIp()`, `@ClientUserAgent()`: parameter
  decorators that resolve the request the same way (GraphQL or HTTP).

### `user` feature to implement
- `AuthService` (domain): `registerLocal` (existing email → `ConflictError USER_EXISTS`, via a
  `P2002` translated by the repository; creation of `User` + `AuthMethod` in a single transaction;
  argon2 hashing), `loginLocal` (`argon2.verify` → otherwise `UnauthenticatedError
  INVALID_CREDENTIALS`), generation of a JWT access token (`sub`, `email`, `sid`) + an opaque
  random refresh token of which only the hash is stored in `user_sessions`.
- Refresh token rotation: on each refresh, the old hash moves into
  `previousRefreshTokenHash` + `rotatedAt`; the old token stays accepted for
  `REFRESH_TOKEN_GRACE_PERIOD` seconds (concurrent requests), after that → `UNAUTHENTICATED`. The
  session update is conditional (`updateMany` on the expected hash) so that a concurrent refresh
  cannot overwrite a rotation already done.
- Commands: `UserRegisterCommand`, `UserLoginCommand`, `UserRefreshTokenCommand`,
  `UserLogoutCommand` (current session), `UserLogoutAllCommand`. Query: `GetCurrentUserQuery`.

### `project` feature to implement
Commands `CreateProjectCommand`, `UpdateProjectCommand(id, userId, params)`,
`DeleteProjectCommand(id, userId)` (soft delete); queries `GetProjectQuery(id, userId)`,
`GetProjectsQuery(userId, search?)` (`name: { contains: search, mode: 'insensitive' }`),
`GetProjectsByIdsQuery(ids)` (for the DataLoader). All reads/writes are scoped by `userId` (a
project belonging to another user = `PROJECT_NOT_FOUND`).

## 7. API layer: GraphQL

### Resolvers
- Inject `CommandBus` / `QueryBus` (and DataLoaders) — **never** a repository or a handler.
- One method per operation; they build the Command/Query from the validated input +
  `@CurrentUser()`, dispatch it, then map it with `XxxType.fromDomain(model)`.

```ts
@Mutation(() => ProjectType)
async createProject(
  @Args('input') input: CreateProjectInput,
  @CurrentUser() user: AuthenticatedUser,
): Promise<ProjectType> {
  const project = await this.commandBus.execute(
    new CreateProjectCommand({ id: input.id, name: input.name, ownerId: user.id }),
  )
  return ProjectType.fromDomain(project)
}
```

### Inputs / Types
- `@InputType()` with `@Field()` **and** `class-validator` decorators (deliberate double
  validation: pipe + Command). Nested objects: `@ValidateNested({ each: true })` +
  `@Type(() => X)`.
- `@ObjectType('Project')` with `static fromDomain(model)`. Relations are resolved lazily via
  `@ResolveField` + DataLoader.

### DataLoaders
`@Injectable({ scope: Scope.REQUEST })`, one instance `new DataLoader<string, T>(async ids => ...)`
which dispatches **a single** `GetXxxByIdsQuery` and then reorders the results via a `Map`
(`ids.map(id => map.get(id) ?? null)`).

### Operations
- `AuthResolver`: mutations `register`, `localLogin`, `refreshToken` (`@Public()`, return
  `AuthTokens { accessToken, refreshToken }`), `logout`, `logoutAll` (→ `Boolean`), query `me`.
- `ProjectResolver`: `projects(filter)`, `project(id)`, `createProject`, `updateProject`,
  `deleteProject`.

### Schema script
`src/scripts/generate-schema.ts`: `NestFactory.createApplicationContext(GraphQLSchemaBuilderModule)`
+ `GraphQLSchemaFactory.create(Object.values(resolvers), [JSONScalar])` → writes `src/schema.gql`
(used by the Docker build; production reads this file).

## 8. API layer: REST (Zod + Swagger)

### Controllers
Same rules as the resolvers: they inject `CommandBus` / `QueryBus` only, one method per route,
build the Command/Query from the validated DTO + `@CurrentUser()`, dispatch it, then map it with
`XxxResponseDto.fromDomain(model)`. They **never** return a raw domain model.

```ts
@ApiTags('projects')
@ApiBearerAuth()
@Controller({ path: 'projects', version: '1' })
export class ProjectController {
  constructor(
    private readonly commandBus: CommandBus,
    private readonly queryBus: QueryBus,
  ) {}

  @Post()
  @HttpCode(201)
  @ApiOperation({ summary: 'Create a project' })
  @ApiCreatedResponse({ type: ProjectResponseDto })
  @ApiErrorResponses(400, 401, 429)
  @ZodSerializerDto(ProjectResponseDto)
  async create(
    @Body() body: CreateProjectDto,
    @CurrentUser() user: AuthenticatedUser,
  ): Promise<ProjectResponseDto> {
    const project = await this.commandBus.execute(
      new CreateProjectCommand({ id: body.id, name: body.name, ownerId: user.id }),
    )
    return ProjectResponseDto.fromDomain(project)
  }

  @Get(':id')
  @ApiOkResponse({ type: ProjectResponseDto })
  @ApiErrorResponses(400, 401, 404)
  @ZodSerializerDto(ProjectResponseDto)
  async findOne(
    @Param() params: ProjectIdParamsDto,
    @CurrentUser() user: AuthenticatedUser,
  ): Promise<ProjectResponseDto> {
    const project = await this.queryBus.execute(new GetProjectQuery(params.id, user.id))
    return ProjectResponseDto.fromDomain(project)
  }
}
```

If the installed version of `nestjs-zod` provides `@ZodResponse({ type, status })` (which both
documents **and** serializes in a single decorator), use it instead of the pair
`@ApiOkResponse` + `@ZodSerializerDto`.

### DTOs: one `dto/<feature>.dto.ts` file per feature
- The **Zod schema is the single source** for validation, the TypeScript type and the Swagger
  documentation. Each field carries `.describe('…')`; examples and component identifiers through
  `.meta({ example, id })`. No manual `@ApiProperty`.
- Requests: `class XxxDto extends createZodDto(XxxSchema) {}` for `@Body()`, `@Param()` and
  `@Query()` (query string: `z.coerce.number()` / `z.stringbool()` for scalars).
  `z.strictObject` on the body to reject unknown fields.
- Responses: an output Zod schema (dates as `z.iso.datetime()`, never a `Date` object) + a class
  with `static fromDomain(model)` that is the only mapping from model → JSON.
- DTOs **never** reuse the types generated by Prisma: they describe the public contract, not the
  table.

```ts
export const CreateProjectSchema = z.strictObject({
  id: z.uuid().optional().describe('Client-generated identifier (UUID v4), optional'),
  name: z
    .string()
    .trim()
    .min(1)
    .max(120)
    .describe('Project name')
    .meta({ example: 'Launch v2' }),
})
export class CreateProjectDto extends createZodDto(CreateProjectSchema) {}

export const UpdateProjectSchema = CreateProjectSchema.omit({ id: true }).partial()
export class UpdateProjectDto extends createZodDto(UpdateProjectSchema) {}

export const ProjectIdParamsSchema = z.object({
  id: z.uuid().describe('Project identifier'),
})
export class ProjectIdParamsDto extends createZodDto(ProjectIdParamsSchema) {}

export const ListProjectsQuerySchema = z.object({
  search: z.string().trim().min(1).optional().describe('Filter on the name (case-insensitive)'),
})
export class ListProjectsQueryDto extends createZodDto(ListProjectsQuerySchema) {}

export const ProjectResponseSchema = z
  .object({
    id: z.uuid(),
    name: z.string(),
    isActive: z.boolean(),
    createdAt: z.iso.datetime().describe('Creation date (ISO 8601, UTC)'),
    updatedAt: z.iso.datetime().describe('Last modification (ISO 8601, UTC)'),
  })
  .meta({ id: 'Project', description: "A user's project" })

export class ProjectResponseDto extends createZodDto(ProjectResponseSchema) {
  static fromDomain(project: Project): ProjectResponseDto {
    return {
      id: project.id,
      name: project.name,
      isActive: project.isActive,
      createdAt: project.createdAt.toISOString(),
      updatedAt: project.updatedAt.toISOString(),
    }
  }
}
```

## 11. Recipe: add a feature (to be documented in `ARCHITECTURE.md`)

For a new `Tag` aggregate:
1. `Tag` model in `prisma/schema.prisma` (`@@map`, `@map`, index), then
   `pnpm db:migrate --name add-tag`; review the generated SQL.
2. Domain model `shared/types/tag.type.ts` (pure class).
3. Mapper `infrastructure/database/mappers/tag.mapper.ts` (`toTag(record: TagRecord)`) + barrel.
4. Repository `infrastructure/database/repositories/tag.repository.ts` (via `txHost.tx.tag`,
   `rethrowPrismaError` on writes) + barrel (registered automatically by
   `Object.values(repositories)`).
5. Commands / Queries `domain/tag/{commands,queries}/*.ts` + barrels.
6. Handlers `domain/tag/handlers/*.handler.ts` (`@Transactional()` if several writes) +
   `*.spec.ts` + barrel.
7. `domain/tag/index.ts`; `export * from './tag'` in `domain/index.ts`;
   `...Object.values(tagHandlers)` in `DomainModule`.
8. Error codes in `ERROR_CODES` + `fr`/`en` translations.
9. GraphQL: `inputs/tag.inputs.ts`, `types/tag.type.ts` (`fromDomain`),
   `resolvers/tag.resolver.ts` (+ barrels); DataLoader if `Tag` is a nested field.
10. REST: `dto/tag.dto.ts` (described Zod schemas + `createZodDto` + `fromDomain`),
    `controllers/tag.controller.ts` (`@ApiTags`, `@ApiErrorResponses`, versioned) + barrel.
11. If the feature needs environment variables: `shared/config/tag.config.ts` (Zod schema +
    `parseEnv`) and `.env.example`.

A feature may exist on only one of the two transports: steps 1 to 8 do not change.

## 12. Forbidden anti-patterns

- A resolver or controller that calls a repository or `PrismaService` directly, or that contains
  business logic.
- A handler that injects `PrismaService` or handles a transaction client: it goes through the
  repositories and `@Transactional()`.
- A handler that returns a Prisma record, a GraphQL type or a REST DTO.
- A Prisma-generated type or enum imported outside `infrastructure/database/`.
- A repository that uses `this.prisma.<model>` instead of `this.txHost.tx.<model>` (it would
  silently leave the current transaction).
- A read that forgets the `deletedAt: null` filter.
- A repository method that accepts a Prisma `where` supplied by the caller.
- Letting an expected Prisma error (`P2002`, `P2025`) propagate without translating it into an
  `AppError`.
- `prisma db push` or `migrate dev` outside development; modifying an already applied migration;
  migrating at application startup.
- A controller that returns a domain model without going through `XxxResponseDto.fromDomain`.
- A domain model or repository that imports from `api/`.
- Joi or TypeORM anywhere; class-validator in `api/rest/` or in the config; a manual
  `@ApiProperty` on a Zod DTO; a REST DTO field without `.describe()`.
- Reading `process.env` anywhere other than in a Zod config file.
- Duplicating a guard, a decorator, or the error logging/translation logic per transport instead
  of writing it once in `api/common/`.
- Omitting the `class-validator` decorators of a Command/Query on the grounds that the DTO or
  input is already validated.
- Returning `null` for a resource that is expected to exist instead of throwing `NotFoundError`.
- Throwing an error with a code absent from `ERROR_CODES` or without a translation.
- A `console.log` instead of the `LoggerService`.

## Deliverables and final verification

1. All the files above, with `README.md` (getting started: `cp .env.example .env`,
   `docker compose -f compose.dev.yml up`, GraphiQL and Swagger URLs, `db:*` commands) and
   `ARCHITECTURE.md` (layers, validation rule, Prisma persistence, recipe §11).
2. Run and fix until everything passes: `pnpm install`, `pnpm db:validate`,
   `biome ci .`, `pnpm build`, `pnpm test`, `pnpm generate-schema`.
3. On an empty local Postgres database: `pnpm db:deploy` then `pnpm db:seed` twice in a row
   (the second run must change nothing).
4. Check that a missing or invalid environment variable makes startup fail with a readable Zod
   message listing all errors.
5. Start the API and check:
   - **GraphiQL**: `register` → `me` (with Bearer) → `createProject` → `projects` →
     `refreshToken` → `logout`; `project(id: "<unknown uuid>")` returns HTTP 200 with
     `extensions.code = "PROJECT_NOT_FOUND"` and a French message (English with
     `Accept-Language: en`); a second `register` with the same email returns `USER_EXISTS`.
   - **REST** (curl): the same journey on `/v1/...`; `GET /v1/projects/<unknown uuid>` returns
     **404** `{ code: "PROJECT_NOT_FOUND", message, correlationId }`; a `POST /v1/projects` with
     `name: ""` returns **400** `VALIDATION_FAILED` with translated `fields`; without Bearer →
     **401**; a deleted project no longer appears in `GET /v1/projects`.
   - **Swagger** (`/docs`): each route shows descriptions and examples taken from the Zod schemas,
     the `ErrorResponse` schema with the `ErrorCode` enumeration, and the Bearer auth button.
